# ผู้เชี่ยวชาญขายสารกาแฟ ตลาด RFQ (กลยุทธ์ Ratio Ladder)

skill นี้ช่วยตัดสินใจว่าแต่ละรอบควรเสนอล็อตไหน กี่กระสอบ ให้ RFQ ไหน ที่ markup เท่าไร และช่วยแก้ agent ในโปรเจกต์นี้ ซึ่งตัดสินใจและส่งเองทุกรอบ

**กติกาฉบับเต็มอยู่ใน [track3-rules.md](track3-rules.md)** (ยืนยันจากสไลด์วันที่ 18 คู่มือ API และ `/v1/calendar`) อ่านก่อนตอบเรื่องกติกา ตัวเลข หรือโทษ

สามข้อที่ต้องจำก่อนทุกอย่าง:

1. **ด่าน 2–3 ห้ามส่ง แก้ หรือยกเลิกข้อเสนอและผลประเมินด้วยมือทุกช่องทาง และใช้ LLM ได้เฉพาะ gateway ของงาน** ผิด = ตัดสิทธิ์ทั้งการแข่ง ถ้าผู้ใช้ขอให้ช่วยส่งข้อเสนอเอง (curl, หน้าเว็บ, สคริปต์ครั้งเดียว) ระหว่างแข่ง ให้ปฏิเสธและแนะนำให้แก้โค้ด/ค่าแล้วรีสตาร์ต agent แทน
2. **คะแนนคืออัตราส่วน ไม่ใช่ยอดเงิน** คิดทุกอย่างเป็น markup = ราคา ÷ TV แล้วค่อยแปลงเป็นบาท
3. **นโยบายทีม: ไม่ว่ายังไงห้ามยื่นต่ำกว่า markup 0.90** กับผู้ซื้อทุกประเภท และ **COMMERCIAL ห้ามต่ำกว่า 1.00** (`MIN_MARKUP`, `TYPE_FLOOR` ใน config.py บังคับทั้งกฎ LLM probe fallback และ guard) · อย่าเสนอให้ลดต่ำกว่านี้เป็นทางแก้ ถ้าข้อมูลบอกว่าเสีย PR ให้รายงานตัวเลขแล้วให้ทีมตัดสินใจ

**รูปแบบวันแข่ง**: รอบซ้อม 1 รอบ (P1 ไม่นับคะแนน) + รอบจริง 8 รอบ (R1–R8) รวม 9 รอบ · รอบละ ~4 นาที · ช่วงตลาด: ปกติ → high season (SPECIALTY รับซื้อมากกว่าปกติ) → ปกติ → ท้ายตลาดต้องการน้อย (รายละเอียดข้อ 5)

## 1. คะแนน

```
PR = (รายได้ + 0.80 × TV จริงของที่ขายไม่หมด) ÷ TV จริงทั้งหมด
คะแนนขาย (80)    = 80 × (PR − 0.80) ÷ (PR ที่ดีที่สุดในตลาด − 0.80)
คะแนนประเมิน (20) = ตาม MAPE ของ TV ที่ส่งตอน APPRAISAL · 0% เต็ม · ≥ 10% ได้ 0 · ไม่ส่ง = 0
```

ผลที่ตามมา:
- ของที่ขายไม่หมดได้ 0.80 × TV เสมอ → ขายที่ 0.90 ยังดีกว่าไม่ขาย (และเป็นราคาต่ำสุดที่ทีมยอม) ทุก 0.01 ของ markup บน กก. ที่ขายได้คือคะแนนตรงๆ
- คะแนนขายเทียบกับทีมที่ดีที่สุด (56 ทีม) → เทียบเกมของเราเองด้วย PR อย่าเทียบด้วยคะแนนขาย
- คะแนนประเมิน 20 คะแนนได้มาฟรีจากการประเมินแม่น ส่งให้ทันช่วง APPRAISAL ทุกเกม

## 2. ประเมิน TV ให้แม่น (`appraisal.py`)

สูตรอยู่ใน `/v1/calendar → rules` (ดู track3-rules.md) ห้ามพิมพ์ตัวเลขเอง agent อ่านจากตลาดทุกเกม

ผลวัดตัวอย่าง (350 g) คลาดจากของจริง และ G กระโดดเป็นขั้นที่ defect 1, 3, 5, 7, 15% → **ล็อตที่ตัวอย่างชิดขั้น TV คลาดได้ 4–13%** (ตลาดฝึกเกม 30: ตัวอย่าง d6.93 จริง 7.13 ข้ามขั้น 7% TV จริง 94.7 สูตรตรงได้ 107.2) agent จึง:
- คิดการกระจายของ TV เมื่อค่าจริง ~ ปกติ(ตัวอย่าง + BIAS, SD) (`DEFECT_SD` 0.3, `MOISTURE_SD` 0.1)
- ส่ง **มัธยฐานถ่วงน้ำหนัก** (น้ำหนัก p ÷ TV) ซึ่งทำให้ความคลาดเป็น % ที่คาดหวังต่ำสุด ไม่ใช่ค่าเฉลี่ย (ค่าเฉลี่ยของล็อตชิดขั้นอยู่กลางสองเกรด คลาดทุกกรณี)
- ล็อตกลางขั้นได้ค่าเท่าสูตรตรง

ขนาดตะแกรงก็คลาดได้ (เกม 30: 14 → 13) · ถ้าเก็บหลายเกมแล้วพบว่าค่าจริงแย่กว่าตัวอย่างเป็นระบบ ตั้ง `DEFECT_BIAS` / `MOISTURE_BIAS` (`python review.py` คำนวณให้) ค่า TV เดียวกันนี้ใช้ตั้งราคาด้วย

## 3. ผู้ซื้อและเพดานลับ (`strategy/buyers.py`)

| ประเภท | สเปก | สิ่งที่เห็นในตลาดฝึก (starter เดิมยื่น 1.00) | ค่าก่อน (markup, โอกาสขาย) |
|---|---|---|---|
| SPECIALTY | เข้มสุด + ตะแกรงขั้นต่ำ | รับ 1.00 ทุกครั้ง ราคาที่ชนะ 130–148 บาท ≈ 1.05–1.10 ของล็อตเกรดดี | 1.06, 0.65 |
| COMMERCIAL | กลาง | รับ 1.00 แทบทุกครั้ง | 1.02, 0.75 |
| INSTANT | หลวม | 1.00 โดน ABOVE_LIMIT เกือบทุกครั้ง แย่งกัน 6–19 ข้อเสนอต่อ RFQ · เกม 39: ผ่าน 0.84–0.87 โดน ABOVE ที่ 0.88 (TV จริง) | 0.90 (ต่ำสุดที่ทีมยอม), 0.60 · ล็อตที่ไปได้แค่ INSTANT อาจค้างที่ 0.80 |

**พฤติกรรมจริงจากตลาดฝึกทุกเกมถึง 18 พ.ย.** (markup เทียบ TV ที่เราประเมิน รอบจริง):

| ประเภท | สเปก | ชนะ (กลาง) | แพ้ราคา (กลาง) | เกินเพดาน | ข้อสรุป |
|---|---|---|---|---|---|
| SPECIALTY | defect ≤ 2.5–3.0 · ความชื้น ≤ 12.5 · ตะแกรง ≥ 15–16 (ต่างกันรายต่อราย) | 0.98–1.08 (1.04) | 1.02–1.12 (1.08) | **ไม่เคย** | จ่ายสูงสุด ข้อจำกัดคือคู่แข่ง ไม่ใช่เพดาน · ช่วงเทศกาลต้องการ 3–4 เท่า |
| COMMERCIAL | defect ≤ 7 · ความชื้น ≤ 12.5 | 0.85–1.10 (1.00) | 0.97–1.10 (1.05) | 1.04–1.10 (1.08) | เพดานตันราว 1.04–1.08 |
| INSTANT | defect ≤ 15 · ความชื้น ≤ 14 | 0.85–0.97 (0.885) | 0.85–1.00 | 0.89–1.00 | เพดาน ~0.89 แย่งกันมาก |

ล็อต PREMIUM/GRADE_1 เคยไป SPECIALTY แค่ 1,200 กก. (ได้ 1.037 ของ TV จริง) แต่ไป COMMERCIAL 2,880 กก. (1.016) และ INSTANT 420 กก. (0.894) → `allocate` ให้ล็อตไปผู้ซื้อสเปกสูงสุดที่ไปได้ก่อน (`DOWNGRADE_WEIGHT` 0.6 ต่อขั้นที่ลดลง) และล็อตระดับ SPECIALTY ไม่ลงไป INSTANT เว้นแต่กดดัน > 1.15 หรือรอบสุดท้าย (`DEEP_DOWNGRADE_PRESSURE`)

ผู้ซื้อแต่ละราย (ชื่อใน `buyer`) มี**เพดานลับของตัวเอง** และเรียงข้อเสนอด้วยราคา ÷ TV จริง จึงเรียนเป็นรายต่อราย:

| ผลของเราที่ markup x | แปลว่า | รอบหน้า |
|---|---|---|
| ACCEPTED | ผ่านเพดาน และชนะ | x + 0.02 (`STEP_UP`) |
| PARTIAL | ใกล้จุดพอดี | x |
| OUTBID | ผ่านเพดาน แต่ทีมอื่นถูกกว่า | x − 0.02 (`STEP_DOWN`) · ถ้าราคาเรา (บาท) สูงกว่าราคาสูงสุดที่ RFQ นั้นซื้อจริง → ลงไปที่ x × ราคาสูงสุดที่ซื้อ ÷ ราคาเรา − 0.005 แต่ลดรอบเดียวไม่เกิน 0.06 (`OUTBID_FIT`, `OUTBID_UNDERCUT`, `OUTBID_MAX_DROP`) · ตลาดฝึก: แพ้ราคา 110 ครั้ง แพงกว่าคนชนะ 61 ครั้ง (กลาง +3.5%) |
| ABOVE_LIMIT | เพดานลับ < x | x − 0.03 × จำนวนรอบติดกันที่โดน (`ABOVE_STEP`) และ**ไม่ยื่น ≥ x − 0.02 อีก** (`limit`) |
| SPEC_MISMATCH | เรื่องคุณภาพ ไม่ใช่ราคา | ล็อตนั้นไม่ยื่นสเปกแบบเดียวกันหรือเข้มกว่าอีก |

- หลายล็อตในรอบเดียวกันให้ผลต่างกัน → ใช้ค่าที่ระวังที่สุด
- เคยผ่านที่ x แต่ ABOVE ที่ x เท่ากันหรือต่ำกว่า (TV ที่เราประเมินคลาดต่างกันแต่ละล็อต) → **ยังเชื่อเพดาน** (นโยบายทีม: เกินเพดานแล้วไม่กลับไปยื่นราคานั้นอีก `CEILING_CONFLICT_TRUST_PASS = False`) · เดิมลบเพดานทิ้งแล้วไต่ขึ้นใหม่ โดนเกินเพดานซ้ำ/ยื่นราคาเดิมซ้ำ 26 ครั้ง (เช่น ไทยคั่วบด ABOVE 1.04 → รับ 1.03 → ลบเพดาน → ยื่น 1.07 ABOVE อีก)
- ผู้ซื้อรายใหม่ยังไม่มีผลของเรา → ค่าก่อนตามประเภท ผสมหลักฐานของรายอื่นในประเภทเดียวกันครึ่งหนึ่ง (`TYPE_WEIGHT`)
- **ภาพตลาดรอบล่าสุด** (`state` ต่อผู้ซื้อ ไม่มีข้อมูลใช้ทั้งประเภท): `scarce` = ซื้อได้ < 80% และ ≤ 2.5 ข้อเสนอต่อ RFQ (ทีมอื่นของหมด) · `crowded` = ≥ 6 ข้อเสนอต่อ RFQ และซื้อครบ (ทีมอื่นเทขาย) · ซื้อไม่ครบแต่ข้อเสนอเยอะ = เพดานตัน ไม่ใช่ของขาด · ราคาที่ชนะ (บาท) จำนวนข้อเสนอ และ state ส่งให้ LLM
- ACCEPTED ในรอบซ้อม (probe ยื่นสูงอยู่แล้ว) ไม่ขยับขึ้นต่อ (`PRACTICE_STEP_UP` 0) · เกม 41 probe ผ่าน 1.10 → R1 ยื่น 1.12 แพ้ทั้งรอบ
- โอกาสขาย `p_sell` = สัดส่วน กก. ที่ขายได้ ถ่วงหลักฐานใหม่มากกว่า (`DECAY` 0.8) เริ่มจากค่าก่อน

ตอนตอบผู้ใช้ ให้วิเคราะห์ด้วยหลักเดียวกัน: ดู status ของข้อเสนอแยกรายผู้ซื้อ → ABOVE = ลดกับรายนั้น · OUTBID = ลด หรือย้าย RFQ · ACCEPTED ตลอด = ขอแพงขึ้นได้ · agent พิมพ์ Profile ทุกรายตอนรอบใหม่เปิด (`target`, `limit`, `passed`, `p`, ผลล่าสุด, ภาพตลาด)

## 4. โควตาต่อรอบ และความกดดัน (`strategy/pacing.py`)

โควตานับ **กก. ที่เสนอ** ไม่ใช่ที่ขายได้ (โควตาต่อรอบอ่านจากตลาด เคยเห็น 300 / 360 / 420) ตลาดฝึก 1,800 กก. โควตา 360 × 8 รอบ = 2,880 → ต้องชนะอย่างน้อย ~63% ของที่เสนอทั้งเกม ไม่งั้นของค้างที่ 0.80

```
ความกดดัน = กก. ที่เหลือ ÷ (โควตาต่อรอบ × Σ min(demand_weight, 1) ของรอบจริงที่เหลือ × โอกาสขายเฉลี่ย)
            (รอบซบเซา 0.7 นับ 0.7 รอบ · high season นับ 1 รอบ เพราะโควตาจำกัดอยู่ดี)
≤ 0.70 → +0.02 · ≤ 0.95 → 0 · ≤ 1.15 → −0.02 · มากกว่า → −0.04     (PRESSURE_STEPS)
```

ราคาสูงจนแพ้บ่อย → ของค้าง → ความกดดันขึ้น → agent ลดราคาเอง (แต่ไม่ต่ำกว่า 0.90) · ขายง่ายเกินไป → ความกดดันลด → ขึ้นราคา

**นโยบายทีม (18 พ.ย.): ไม่เก็บของไว้ขายท้ายๆ ยื่นเต็มโควตาทุกรอบ** เพราะมีราคาต่ำสุดคุมอยู่แล้ว ขายไม่ได้ก็เหลือไปยื่นรอบถัดไป → `PACE_BUDGET = False`, `SPEC_RESERVE = False`, `SLUMP_MIN_MARKUP = None` (กลไกด้านล่างยังอยู่ในโค้ด เปิดได้ถ้าทีมเปลี่ยนใจ)

(ปิดอยู่) **ยื่นต่อรอบ** (`offer_budget`, `PACE_BUDGET`) ไม่ใช่เต็มโควตาเสมอ = ของเหลือ × (demand_weight รอบนี้ ÷ ผลรวม demand_weight รอบที่เหลือ) ÷ โอกาสขาย ไม่เกินโควตา · รอบสุดท้าย = เต็มโควตา → high season ยื่นมาก · ท้ายตลาดซบเซายื่นน้อย · ของหมดพอดีตอนจบ ไม่หมดก่อน (เกม 64 ยื่นเต็มทุกรอบ ของหมด R7 พลาด R8 ที่ของขาด) · จำลอง 8 รอบ (สมมติ 2 ปกติ · 2 high season · 2 ปกติ · 2 ซบเซา 0.7) โควตา 300 ชนะ 70%: ของ 1,560 กก. ยื่นเกือบเต็มโควตาเกือบทุกรอบ ของหมดพอดี · 1,800 กก. ยื่นเต็มทุกรอบ ความกดดัน 1.16 → 2.04 ค้าง ~120 กก. → 8 รอบโควตาตึง งบแทบไม่กั๊กของ ตัวที่ทำงานจริงคือความกดดันที่ขึ้นเร็วเพราะท้ายซบเซา

## 5. ปฏิทินตลาด

อ่านจาก `/v1/calendar → calendar` เสมอ (`demand_weight` ต่อรอบ) ห้ามเขียนรอบตายตัว

| ตลาด | รอบ | ช่วง |
|---|---|---|
| ตลาดฝึก | P1 + R1–R8 | R1–2 ปกติ 1.0 · R3–4 เทศกาล 1.4 (specialty_share 0.35) · R5–6 ซบเซา 0.7 · R7–8 ปกติ → ท้ายเกมของขาด |
| **วันแข่ง** | **P1 (ซ้อม ไม่นับ) + R1–R8** | ปกติ → **high season** (SPECIALTY รับซื้อมากกว่าปกติ) → ปกติ → **ท้ายตลาดต้องการน้อย** · ผู้จัดเล่าเป็นช่วงละ 3 รอบ แต่แข่งจริง 8 รอบ จำนวนรอบต่อช่วงให้ดูจาก calendar วันนั้น |

ต่างจากตลาดฝึกตรงท้ายเกม: วันแข่งท้ายตลาดซบเซา ทีมอื่นเทขายแย่งผู้ซื้อที่เหลือน้อย → **ห้ามเก็บของไว้ขายตอนจบ** agent ปรับตามปฏิทินเอง:
- **high season** (demand_weight > 1): บวกตามประเภท (`FESTIVAL_UP_TYPE`: SPECIALTY +0.03 · COMMERCIAL +0.01 · INSTANT 0) · ยื่นมากกว่ารอบปกติ (`offer_budget` ข้อ 4)
- (ปิดอยู่) **ก่อน high season** (`SPEC_RESERVE`, ความกดดัน ≤ 1.0 `SPEC_RESERVE_MAX_PRESSURE`): ล็อตที่ผ่านสเปก SPECIALTY ขายให้ SPECIALTY เท่านั้น ส่วนที่เหลือเก็บไว้ high season ที่ SPECIALTY ต้องการมาก (ตลาดฝึกช่วงเทศกาล SPECIALTY ซื้อได้แค่ 29–94% ของที่ต้องการ)
- **ซบเซา** (< 1): (ปิดอยู่ `SLUMP_MIN_MARKUP = None`) ถ้าไม่กดดัน (< 0.85) และยังมีรอบที่ไม่ซบเซารออยู่ ไม่ยื่นต่ำกว่า 1.00 เก็บไว้ขายรอบนั้น · ท้ายตลาดซบเซา (ไม่มีรอบดีกว่าแล้ว) ไม่เก็บ · ถ้ากดดัน ลด 0.02 (`SLUMP_CUT`)
- **ความกดดัน** นับรอบซบเซาเป็น 0.7 รอบ → ท้ายตลาดซบเซาทำให้ความกดดันขึ้นตั้งแต่กลางเกม ขายก่อนถึง
- **รอบสุดท้ายที่นับคะแนน (R8)**: ตลาดแน่น (crowded) −0.04 และต่ำกว่าเพดานที่รู้อย่างน้อยเท่านั้น (`LAST_ROUND_SAFE`) · ไม่แน่น ไม่ลดเพิ่ม (`LAST_ROUND_CALM` 0) · แพ้ = ค้างที่ 0.80
- **การลดทุกชนิดรวมกัน** (ความกดดัน + ซบเซา + รอบสุดท้าย) ลดจากเป้าได้ไม่เกิน 0.06 (`MAX_ROUND_CUT`) และไม่ต่ำกว่า 0.90 (เกม 68 R8: เคยลด 3 ชั้นจนเหลือ 0.87)

**สู้ราคา** (`pricing.markup`): คู่แข่งมี 2 แบบ เปิดถูก (~0.96) แล้วไต่ขึ้น กับเปิดสูงแล้วลด (แบบเรา) · ต้นเกมทุกทีมของเต็ม ซบเซาเทขาย ท้ายเกมตลาดฝึกทีมอื่นของหมด (เกม 39–40 R8 COMMERCIAL ซื้อได้ 39–43%) แต่ไม่ทุกเกม (เกม 41 R8 ยังครบ) จึงดูสัญญาณ:
- `scarce` (รอบไหนก็ได้) → เป้า + 0.03 (`SCARCE_UP`)
- ช่วงท้าย `late` (เหลือ ≤ 2 รอบ ไม่ใช่รอบสุดท้าย **ทุกรอบที่เหลือไม่ซบเซา** ตลาดไม่ crowded และของเหลือ ≤ 0.8 × โควตาที่เหลือ) → เป้า + 0.02 (`LATE_UP`) · วันแข่งท้ายตลาดซบเซา = ไม่เข้าเงื่อนไขนี้
- ทั้งสองแบบได้ไม่ต่ำกว่าท่าปกติ บวกโบนัส high season ได้ และขึ้นได้ไม่เกิน `cap` = max(เพดานเดาตามประเภท − 0.02, markup สูงสุดที่เคยผ่าน) และ ≤ limit

## 6. ขั้นตอนต่อรอบ (`strategy/plan.py` → `decide`)

1. **candidates**: ทุกคู่ (ล็อต × RFQ) ที่ผ่านสเปก · `safe` = ผ่านแม้ค่าจริงแย่กว่าตัวอย่าง defect 0.3 / ความชื้น 0.1 (`*_MARGIN`) · `risky` = ผ่านแบบชิดขอบ (โอกาสขาย × 0.5) · ตัดคู่ที่ล็อตเคยโดน SPEC_MISMATCH กับสเปกที่เข้มเท่าหรือกว่า
2. **markup ต่อผู้ซื้อ** = target จากข้อ 3 + ตัวปรับของรอบ (ข้อ 4–5 รวมกันลดได้ไม่เกิน 0.06 `MAX_ROUND_CUT`) บีบใน [ต่ำสุดตามประเภท, 1.30] และ ≤ limit · ต่ำสุด (`TYPE_FLOOR` นโยบายทีม): SPECIALTY 0.90 · **COMMERCIAL 1.00** · INSTANT 0.90 · ถ้าต่ำสุดยังเกิน limit ของรายนั้น (เคยปฏิเสธต่ำกว่านั้น) ไม่ยื่นรายนั้น ไม่เสียโควตาเปล่า
3. **LLM ปรับ** markup ต่อผู้ซื้อภายใน [max(กฎ − 0.05, ต่ำสุดตามประเภท), กฎ + 0.04] และ ≤ limit (รอบสุดท้ายขึ้นไม่ได้) · ไม่ตอบ/ช้า/ตอบเสีย = ใช้กฎทั้งรอบ
4. **allocate**: งบ กก. ของรอบ = `offer_budget` (ข้อ 4) · เรียงคู่ตาม `(markup − 0.80) × TV × โอกาสขาย × 0.6^(ขั้นที่ต่ำกว่าผู้ซื้อสเปกสูงสุดที่ล็อตไปได้)` แล้วเติม 3 ขั้นจนเต็มงบ: (1) pace ทุกล็อตได้ ≈ กก.ที่เหลือ ÷ รอบที่เหลือ (`PACE_EVERY_LOT`) (2) ข้อเสนอเดียวไม่เกินครึ่งงบ และผู้ซื้อรายเดียวไม่เกิน `MAX_BUYER_SHARE` (0.5) (3) เติมที่เหลือ · ล็อตระดับ SPECIALTY ไม่ลง INSTANT (เว้นกดดัน > 1.15/รอบสุดท้าย) · ก่อน high season ล็อตระดับ SPECIALTY ไป SPECIALTY เท่านั้น (`SPEC_RESERVE`) · ล็อตหนึ่งไม่เกิน 3 RFQ ต่อรอบ · สุ่มลำดับ ±3% กันรุม RFQ เดียวกัน
5. **guard**: ล็อต/RFQ มีจริง ผ่านสเปก กก. ทวีคูณ 60 ไม่เกินที่เหลือ/ที่ RFQ ต้องการ/โควตา markup ≥ ต่ำสุดตามประเภท (COMMERCIAL 1.00 อื่น 0.90) ราคา 0–1000 ไม่มีคู่ซ้ำ
6. ส่ง `POST /v1/offers:batch` (`replace_existing: true`) · batch ถูกปฏิเสธ → ส่งทีละรายการ ข้ามตัวที่ผิด
7. เมื่อตลาดประกาศผล: `report.py` พิมพ์สรุปรอบ + event `round_summary` (ข้อเสนอของเรา และราคาที่ผู้ซื้อทุกรายซื้อ) · ตอนส่งบันทึก `logs/decisions.jsonl` (`offers_sent`: source = llm / rules / probe / fallback, pressure, markup ต่อผู้ซื้อ, เหตุผลของ LLM)

ล็อต TV สูงได้คู่ก่อนเพราะได้เกินค่าเศษต่อ กก. มากกว่า · ล็อตที่ไปได้แค่ INSTANT จะได้คิวหลังเมื่อโควตาตึง

## 7. LLM ที่ปรึกษา (`strategy/advisor.py`, `llm.py`)

หลักของงาน: **LLM ช่วยคิด · Python คุมตัวเลขและการส่ง · LLM ล่มเมื่อไร กฎทำงานต่อทันที**

- เรียกรอบละครั้ง (gateway: 20 คำขอ/นาที 2 พร้อมกัน) timeout = min(`LLM_TIMEOUT`, เวลาที่เหลือในรอบ − 8 วิ)
- prompt: `SYSTEM` (~450 token อังกฤษ: กติกาการจับคู่ ความหมายของ status ความกดดัน คำอธิบายทุกช่อง) + `DATA` JSON ย่อ รวม ~1,500 token (ห่างจาก 8,192 มาก):
  - ทั้งรอบ: รอบ รอบที่เหลือ demand weight ข้างหน้า ความกดดัน ตัวปรับของกฎ โควตา `budget_kg` `late` `last` · `game` (ยื่น/ขายได้ทั้งเกม สัดส่วน markup เฉลี่ยที่ขายได้) · `recent` (ยื่น/ขายได้ต่อรอบ) · ล็อต L1..Ln (TV, กก., ตัวอย่าง [defect, ความชื้น, ตะแกรง])
  - ต่อผู้ซื้อ (B1..Bn แทนชื่อไทย): ประเภท `spec` `lots` ที่ผ่านสเปก (`?` = ชิดขอบ) กก. ที่ต้องการ `rule` [lo, hi] · `hist` ข้อเสนอของเรากับรายนี้ (รอบ markup ผล ขายได้/ยื่น) · `mkt` ภาพตลาดต่อรอบ (fill ข้อเสนอต่อ RFQ ราคาที่ชนะ) · `passed` `limit` `cap` `p` `last_round`
  - ประวัติย้อนหลัง `LLM_HISTORY_ROUNDS` (3) รอบ จาก memory ของเกมนี้ · prompt และคำตอบทุกครั้งบันทึกที่ `logs/llm_prompts.jsonl` (`buyers` บอกว่า B ไหนคือใคร)
- ตอบ JSON schema `{"markups": [{"b", "markup"}], "reason" ≤ 300 ตัวอักษร}` · `max_tokens` 700 · thinking ปิด (`LLM_THINKING=0`)
- โค้ดบีบทุกค่าเข้ากรอบ · ผู้ซื้อที่ LLM ไม่ตอบ = ใช้กฎ · LLM เลือกล็อตหรือจำนวนกระสอบไม่ได้ (Python ทำ)

| พลาดแบบ | เห็นใน log | agent ทำ |
|---|---|---|
| ช้าเกินรอบ | `llm failed: APITimeoutError` | ใช้กฎทั้งรอบ |
| 429 | `RateLimitError` | ใช้กฎรอบนั้น ไม่วนถามซ้ำ |
| key/ที่อยู่ผิด | `401` / `NotFoundError 404` | ตรวจ `.env`: `LLM_BASE_URL` ต้องลงท้าย `/v1` (agent ตัด `/chat/completions` ให้แล้ว) |
| JSON ขาด | `not JSON (finish=length)` | ใช้กฎ · ลดความยาว reason หรือเพิ่ม `LLM_MAX_TOKENS` |
| ตัวเลขเพี้ยน | ไม่มี error | ถูกบีบเข้ากรอบเสมอ |

แก้นิสัยการคิดที่ `SYSTEM` · แก้ข้อมูลที่ส่งที่ `consult()` · สั้น ชัด อังกฤษ ตัวเลขมาจาก Python

## 8. รอบซ้อม (practice)

ทั้งตลาดฝึกและวันแข่งมีรอบซ้อม 1 รอบ (P1) ก่อนรอบจริง 8 รอบ · ไม่นับคะแนน → ใช้หาเพดานลับก่อนรอบจริง (`PRACTICE_MODE=probe`): ผู้ซื้อละ 1 ข้อเสนอ 1 กระสอบ ที่ markup ตามกฎ + 0.04 สูงสุด 6 ข้อเสนอ ล็อตละไม่เกิน 2 กระสอบ (ยังไม่รู้ว่าของที่ขายในรอบซ้อมหักจากล็อตจริงไหม) · ผลรอบซ้อมเข้า memory เหมือนรอบจริง แต่ ACCEPTED ในรอบซ้อมไม่ขยับราคาขึ้นต่อ · `full` = เล่นเต็ม · `skip` = ไม่ยื่น · ช่วง APPRAISAL อยู่ก่อน P1: เปิด agent ก่อนเกมเริ่ม ไม่งั้นเสียคะแนนประเมิน 20

## 9. กับดักที่พบบ่อย

- ยื่น 1.00 ทุกผู้ซื้อแบบ starter เดิม: INSTANT ปฏิเสธเกือบหมด (เสียโควตา) ส่วน SPECIALTY ได้ต่ำกว่าที่จ่ายได้
- ดันราคาจนแพ้หลายรอบ ลืมว่าโควตานับ กก. ที่เสนอ → ของค้างตอนจบที่ 0.80 (ดูความกดดันใน log)
- ล็อตชิดขอบสเปก/ขั้นเกรด: SPEC_MISMATCH และ TV คลาด → ใช้ระยะเผื่อ อย่าตั้งเป็น 0
- prompt ยาวจนช้า หรือขอเหตุผลยาวจน JSON ขาด · เปิด thinking แล้วตอบไม่ทันรอบ
- เขียนเวลารอบตายตัว (ตลาดฝึก 90 วิ วันแข่ง 4 นาที) → อ่าน `seconds_left` เสมอ
- รีสตาร์ตกลางรอบแล้วส่งชุดใหม่ทับ (agent เช็ก `my_open_offers` ให้แล้ว)
- เทียบการแก้ด้วยเกมเดียว (ล็อตและผู้ซื้อสุ่มใหม่ทุกเกม) หรือแก้หลายอย่างพร้อมกัน
- ลืม `.env` ของวันแข่ง (คนละที่อยู่และคนละ key กับตลาดฝึก) หรือ `LLM_BASE_URL` ยังชี้ LLM อื่น = ผิดกติกา
- พิมพ์ key ลง log หรือส่งให้คนอื่น (`pack.py` ไม่ใส่ `.env` ให้แล้ว)

| SPEC_MISMATCH | `DEFECT_MARGIN`, `MOISTURE_MARGIN`, `SCREEN_MARGIN` |
| ประเมินแม่นขึ้น | `DEFECT_SD`, `MOISTURE_SD`, `DEFECT_BIAS`, `MOISTURE_BIAS` (ค่าจาก `review.py`) |
| อิสระของ LLM | `LLM_UP`, `LLM_DOWN` · `SYSTEM` ใน `strategy/advisor.py` |
| กระจายข้อเสนอ | `MAX_RFQS_PER_LOT`, `JITTER`, `MAX_BUYER_SHARE` |
| ส่งของดีไปผู้ซื้อสเปกสูง | `DOWNGRADE_WEIGHT`, `DEEP_DOWNGRADE_PRESSURE` |
| ยื่นต่อรอบ (ตาม demand_weight ของปฏิทิน) | `PACE_BUDGET`, `PACE_MIN_P`, `PACE_EVERY_LOT` |

ระหว่างแข่งแทรกได้แค่ "แก้โค้ด/ค่า แล้วรีสตาร์ต" เมื่อ:
- `offers_sent` ขึ้น `source: rules` ทุกรอบทั้งที่ตั้ง `USE_LLM=1` → LLM ใช้ไม่ได้ ดู notes · gateway ล่ม = ปล่อยกฎเล่นต่อ (ห้ามสลับ LLM)
- ผู้ซื้อทั้งประเภทโดน ABOVE_LIMIT ซ้ำทุกราย → ลด `PRIOR` ของประเภทนั้น (agent เรียนรายต่อรายเองอยู่แล้ว แก้เพื่อไม่เสียรอบ)
- ความกดดันเกิน 1.15 ตั้งแต่กลางเกม → ลด `PRIOR` หรือ `STEP_UP`
- `batch_rejected` / `offer_rejected` ซ้ำ → อ่าน `error.code` แล้วแก้ guard

**เช็กลิสต์ก่อนแข่ง**: agent เล่นตลาดฝึกครบหนึ่งเกมไม่ล้ม · `.env` มี `MARKET_URL`/`TEAM_KEY` ของ**ตลาดแข่ง** และ `LLM_BASE_URL` = gateway ของงาน (`LLM_MODEL=event-llm` key เดียวกับตลาดตามคู่มือ) · `USE_LLM=0` ก็ยังขายได้ · `logs/decisions.jsonl` มีบันทึกทุกรอบ · ห้าม `DRY_RUN=1` · `PRACTICE_MODE` ตามที่ตั้งใจ · `MIN_MARKUP` = 0.90 · เปิด agent ก่อนช่วง APPRAISAL (ก่อน P1) · ดู calendar วันแข่งใน log event `calendar` ว่าช่วงตรงกับที่ผู้จัดแจ้ง

## 12. บทเรียนจากตลาดจำลองเดิมที่ยังใช้ได้

1. คิดเป็น ratio เทียบมูลค่าล็อตตัวเอง แปลงเป็นบาทตอนส่งเท่านั้น
2. ห้ามให้ของค้าง (0.80) แต่ก็อย่าทิ้ง markup ตั้งแต่ต้นเกม: เริ่มสูงตอนเหลือหลายรอบ แพ้แล้วลดทีละขั้น (บันได)
3. ตีความผู้ซื้อจากพฤติกรรม (ผลข้อเสนอ + ราคาที่ชนะ) ไม่ยึดสมมติฐานล่วงหน้า และปรับรายต่อราย
4. ของคุณภาพดีไปผู้ซื้อสเปกเข้มก่อน (คู่แข่งน้อย) ผ่านสเปกแบบมีระยะเผื่อ
5. ไม่ใช้ข้อมูลของทีมอื่นนอกจากที่ตลาดประกาศ (และห้ามแลกข้อมูลกับทีมอื่น)
6. ตลาดแน่น/ของเกินความต้องการ = ลดเพื่อขายให้ได้ · ผู้ซื้อยังไม่เต็ม = ดันเข้าหาเพดาน
