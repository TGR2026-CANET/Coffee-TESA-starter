## ตลาด

- **ล็อต**: น้ำหนักเป็น กก. ทวีคูณ 60 (1 กระสอบ) · ผลวัดตัวอย่าง `sample` = defect_pct, moisture_pct, screen (ตัวอย่าง 350 g คลาดจากของจริง)
- วันแข่ง**ทุกทีมได้โจทย์ล็อตเดียวกัน**: ช่วง 1 เหมือนกันทุกอย่าง ต่างแค่ lot_id · ช่วง 2–3 ขนาด เกรด และผู้ซื้อที่รับได้เหมือนกัน ความคลาดของตัวอย่างเท่ากัน ค่าตำหนิ/ความชื้นขยับเล็กน้อยต่อทีม ลำดับล็อตสลับ · ตลาดฝึกสุ่มล็อตใหม่ทุกเกม
- **RFQ**: แต่ละรอบผู้ซื้อประกาศ RFQ (rfq_id, buyer, buyer_type, kg, spec) · ประเภทผู้ซื้อ 3 แบบ **SPECIALTY** (จ่ายสูงสุด สเปกเข้มสุด มีขนาดตะแกรงขั้นต่ำ) · **COMMERCIAL** · **INSTANT** (จ่ายน้อยสุด สเปกหลวม) · ตลาดฝึกมีผู้ซื้อ 7 ราย (SPECIALTY 2, COMMERCIAL 3, INSTANT 2)
- **ข้อเสนอ**: (rfq_id, lot_id, kg, price_per_kg) · ล็อตเดียวเสนอหลาย RFQ ได้ แต่ กก. รวมไม่เกินที่มี · ไม่เกิน kg ของ RFQ · ราคา 0–1000 บาท/กก.
- **โควตาต่อรอบ**: เสนอรวมได้ไม่เกิน `round_capacity_kg` (≈ 1.5 × กก.ทั้งหมด ÷ จำนวนรอบ ปัดเป็นกระสอบ เช่น 1,800 กก. 8 รอบ → 360) ดู `capacity_left_kg` · **นับ กก. ที่เสนอ ไม่ใช่ที่ขายได้** ข้อเสนอที่แพ้ = เสียโควตารอบนั้น
- **การจับคู่** (ต่อ RFQ): ตัดข้อเสนอที่ไม่ผ่านสเปก (ตรวจกับ**คุณภาพจริง**) และเกินเพดานลับของผู้ซื้อ → เรียง **ราคา ÷ TV จริง** ต่ำไปสูง → รับจนครบ กก. → จ่ายตามราคาที่เสนอ · คุ้มเท่ากันแบ่งกันทีละกระสอบ · ข้อเสนอหมดอายุเมื่อรอบปิด
- **ปฏิทิน** (`/v1/calendar` → calendar) ตลาดฝึก: R1–2 ปกติ (1.0) · R3–4 **เทศกาล** (demand 1.4, specialty_share 0.35) · R5–6 **ซบเซา** (0.7) · R7–8 ปกติ
- รอบ `practice` ไม่นับคะแนน (`round.counts_for_score`) ⚠ ยังไม่ยืนยันว่าของที่ขายในรอบซ้อมหักจากล็อตจริงหรือไม่

### ผลข้อเสนอ (`last_results.my_offers[].status`)

| status | ความหมาย | ทำอะไรรอบหน้า |
|---|---|---|
| `ACCEPTED` | ขายได้ครบ | ขอแพงขึ้นเล็กน้อย (ขายได้ตลอด = อาจถูกไป) |
| `PARTIAL` | ขายได้บางส่วน | ใกล้จุดพอดี |
| `OUTBID` | ผ่านเพดาน แต่ข้อเสนออื่นคุ้มกว่า RFQ เต็มก่อน | ลดราคา หรือไป RFQ อื่น |
| `ABOVE_LIMIT` | แพงเกินเพดานลับของผู้ซื้อรายนั้น | ลดตัวคูณกับผู้ซื้อรายนั้น/ประเภทนั้น |
| `SPEC_MISMATCH` | คุณภาพจริงไม่ผ่านสเปก (ตัวอย่างคลาด) | ระวังล็อตที่ใกล้ขอบสเปก |
| `CANCELLED` | ยกเลิกเอง หรือถูกแทนด้วย `replace_existing` | — |

`market_summary` ต่อ RFQ: wanted_kg, bought_kg, offers (จำนวนข้อเสนอ), price_min/avg/max (บาท/กก. ของที่ซื้อจริง) ไม่บอกทีม

## มูลค่าจริง (TV) และคะแนน

```
TV = p0 × G × M × S          (บาท/กก. · ตลาดฝึก p0 = 120)
G = (1 − d/100) × step ของขั้นแรกที่ d ≤ max_defect_pct
    ≤1% PREMIUM 1.08 · ≤3% GRADE_1 1.04 · ≤5% GRADE_2 1.00 · ≤7% GRADE_3 0.96 · ≤15% BELOW_STANDARD 0.85 · อื่นๆ REJECT 0.60
M = 1 ถ้า m ≤ 12.5 · ถ้า m ≤ 15: (1 − m/100)/(1 − 0.125) − 0.02 × (m − 12.5) · เกิน 15: 0.6
S = ตามขนาดตะแกรง 12: 0.92 · 13: 0.97 · 14–15: 1.00 · 16–17: 1.03 · 18: 1.06
```

- **PR** = (รายได้ + 0.80 × TV จริงของที่ขายไม่หมด) ÷ TV จริงทั้งหมด · 1.00 = ขายได้เท่ามูลค่าจริง
- **คะแนนขาย** (80) = 80 × (PR − 0.80) ÷ (PR ที่ดีที่สุดในตลาดเดียวกัน − 0.80) → เทียบกับทีมที่ดีที่สุด เทียบเกมของเราเองด้วย PR
- **คะแนนประเมิน** (20) จากความคลาดเฉลี่ย (MAPE) ของ TV ที่ส่งเทียบ TV จริง · 0% เต็ม · ≥ 10% ได้ 0 · ไม่ส่ง = 0
- ตลาดฝึกดูเฉลยได้ที่ `GET /v1/sandbox/reveal` หลังปิดตลาด (ราว 5 นาทีก่อนเกมใหม่) · วันแข่งไม่มี

## API ที่ agent ใช้ (`Authorization: Bearer <TEAM_KEY>` ทุกคำขอ · ไม่เกิน 5 ครั้ง/วินาที)

| phase | agent ทำ |
|---|---|
| `WAITING` / `SETUP` | รอ (SETUP เห็นล็อตแล้ว คำนวณ TV ได้) |
| `APPRAISAL` | `POST /v1/appraisals` `{"items": [{lot_id, est_value_per_kg, grade?}]}` ครั้งเดียว |
| `ROUND_OPEN` | `POST /v1/offers:batch` `{"offers": [...], "replace_existing": true}` ทั้งหมดหรือไม่มีเลย |
| `ROUND_CLEARING` | รอผล |
| `CLOSED` | อ่านผล (ตลาดฝึก: reveal) |

- `GET /v1/state` ทุกอย่างในครั้งเดียว: phase, seconds_left, round (round_id, kind, number, of, calendar), lots (kg_available), rfqs, my_open_offers, round_capacity_kg, capacity_left_kg, appraisal_submitted, last_results, standings
- รีสตาร์ตกลางรอบ: ถ้า `my_open_offers` มีข้อเสนอของรอบนี้แล้ว อย่าส่งชุดใหม่ (capacity_left_kg หักไปแล้ว ชุดใหม่จะเล็กกว่าและแทนชุดเดิม)
- error ใช้รูป `{"error": {code, message, field, hint, allowed}}` เช่น `OVER_ROUND_CAPACITY`, `EXCEEDS_REMAINING`, `NOT_MULTIPLE_OF_BAG`, `BATCH_REJECTED` (`allowed.errors[].index`), `WRONG_PHASE`, `RATE_LIMITED`

## LLM gateway ของงาน

| เรื่อง | ค่า |
|---|---|
| API | OpenAI-compatible `http://<gateway>:4000/v1` (ไลบรารี openai ต่อ `/chat/completions` เอง) |
| key / model | key เดียวกับตลาด · `event-llm` (โมเดลขนาดเล็ก ทุกทีมใช้ตัวเดียวกัน GPU ร่วมกัน) |
| context | **8,192 token ต่อการเรียก** (prompt + คำตอบ) ล้น = gateway ตอบ error |
| จำกัด | 2 คำขอพร้อมกันต่อทีม · 20 คำขอ/นาที · max_tokens ≤ 2000 |
| thinking | ปิดเป็นค่าเริ่มต้น · `reasoning_effort="medium"` เปิด (ช้ามาก อาจคิดจน token หมด) |
| JSON | `response_format={"type": "json_schema", ...}` |

error: `BAD_KEY` 401 · `TOO_MANY_CONCURRENT` 429 · `RATE_LIMIT` 429 (รอตาม Retry-After) · timeout ต้องจบก่อนรอบปิด

## สิ่งที่ยังไม่รู้

- ของที่ขายในรอบซ้อมหักจากล็อตและไม่นับรายได้หรือไม่ (agent ตั้งค่า `PRACTICE_MODE=probe` ยื่นน้อยไว้ก่อน)
- เพดานลับคิดเทียบ TV จริง (ตัวคูณ) หรือเป็นบาท · ข้อมูลตลาดฝึกเข้ากับแบบตัวคูณ (ข้อเสนอ markup 1.00 เดียวกันกับ INSTANT รายเดียว ล็อตหนึ่ง ABOVE_LIMIT อีกล็อต OUTBID = TV ที่เราประเมินคลาด)
- ผลวัดตัวอย่างคลาดแบบมีทิศทาง (bias) หรือไม่: เกม 30 ตลาดฝึก defect จริงสูงกว่าตัวอย่างทั้ง 4 ล็อต (+0.16 ถึง +0.39) ตะแกรง 14 → 13 หนึ่งล็อต · เก็บเพิ่มด้วย `python review.py`
- ปฏิทินและจำนวนผู้ซื้อของวันแข่ง (อ่านจาก `/v1/calendar` ตอนเริ่ม agent พิมพ์ให้ดู)
